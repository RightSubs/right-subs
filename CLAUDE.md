# RightSubs — context for Claude

Packs the [RightSubs](rightsubs/) Stremio addon (Node.js; its own context in [rightsubs/CLAUDE.md](rightsubs/CLAUDE.md)) into an APK for Android TV/Google TV and phones: no Termux, credentials typed on first launch and stored securely. Public repository of the **RightSubs** GitHub organization (`RightSubs/right-subs`), open to contributors, under the GPL-3.0-or-later ([LICENSE](LICENSE)).

**Language rule:** the maintainers talk to Claude in Portuguese, so **replies to the user are in Portuguese**. **Everything in the repository is in English**: code, identifiers, comments, logs, error messages, scripts and their output, tests, skills, docs, CHANGELOG and commit messages. The only exceptions are user-facing translations: the app's Portuguese strings (`android/app/src/main/res/values-pt/strings.xml`, next to the English default in `values/`) and the messages shown inside Stremio (`rightsubs/src/i18n/messages.ts`, one fixed translation per language in `LANGUAGES`). Test data may hold subtitle lines in other languages.

Documentation for people: [README.md](README.md). This machine's environment (box IP etc.) lives in `CLAUDE.local.md`, **outside git**.

## Architecture (decided; do not reopen without a reason)

| Part | How |
|---|---|
| Node.js | Termux's `nodejs-lts` (24.22.1 today, the one validated on the box), extracted from the `.deb` files ([scripts/termux-node.mjs](scripts/termux-node.mjs)): SHA-256 checked against the index, dependencies by BFS over `NEEDED`. nodejs-mobile was ruled out (stuck on Node 18; RightSubs uses `util.parseEnv`). |
| Libraries | Android only extracts `lib*.so` from the APK: `libssl.so.3` becomes `libssl_so_3.so`; `assets/libmap.txt` keeps the map and the app creates symlinks with the real name in `files/lib/` (no patchelf). `LD_LIBRARY_PATH=files/lib:nativeLibraryDir`. |
| Executables | Node and ffmpeg in `jniLibs` as `libnode.so`, `libffmpeg.so`, `libffprobe.so` (the only executable folder for targetSdk ≥ 29; `useLegacyPackaging = true`). `files/bin/{node,ffmpeg,ffprobe}` are symlinks; `PATH` points there, so RightSubs finds `ffmpeg` unchanged. |
| ffmpeg | 7.1.1 **minimal**, built with the NDK ([scripts/build-ffmpeg.sh](scripts/build-ffmpeg.sh)): only text-subtitle demuxers/decoders/encoders, http(s). TLS through Termux's OpenSSL. Patch [patches/ffmpeg-tls-verify.patch](patches/ffmpeg-tls-verify.patch): verifies certificate **and** hostname by default. Cached by hash in `build/cache/ffmpeg/`. |
| RightSubs | **Lives only in `rightsubs/`** (it started as a copy of the standalone right-subs project on 2026-11-01). `git archive HEAD:rightsubs` → `npm ci --ignore-scripts`, build, `npm prune --omit=dev` → `assets/rightsubs.zip` ([scripts/build-payload.sh](scripts/build-payload.sh)). The app unzips it into `files/app/` on every version (zip-slip protected). |
| Config | The app generates `files/config.yaml` from `config.example.yaml` ([ConfigWriter.kt](android/app/src/main/java/com/rightsubs/android/ConfigWriter.kt)): host `127.0.0.1`, port 7000, `realdebrid.enabled` = there is a token, `translation.deepl.enabled` = there is a DeepL key, `stremio.enabled` always, `languages.primary`/`secondary` and `sync.referenceLanguages` from the screen ([Languages.kt](android/app/src/main/java/com/rightsubs/android/Languages.kt): common choices, default pt-BR + pt-PT, reference `en`; secondary "None" comments the line out, reference "None" writes `[]`. Credential validation returns `CredentialError` codes (string resources); `PhoneSetupServer` gets every page text through `text: (Int) -> String` (`Context::getString`). A new string goes into **both** files. |

## Credentials security (a requirement)

- AES-256-GCM with a key from the **Android Keystore** (StrongBox when available), AAD = field name ([SecretStore.kt](android/app/src/main/java/com/rightsubs/android/SecretStore.kt)). Lost/invalid key → delete and ask again.
- Secrets only as **environment variables** of the Node process (clean environment, `environment().clear()`); never in a file nor on the command line (`OPENSUBTITLES_*`, `RD_TOKEN`, `DEEPL_API_KEY`). No `.env` on the device. The five fields (RD and DeepL optional) are on the screen and in the "Fill in on your phone" form.
- `allowBackup=false` + empty extraction rules; `FLAG_SECURE`; `textPassword` fields, `flagNoPersonalizedLearning`, no autofill, `saveEnabled=false`; saved values never show again (a blank field keeps them).
- Log: every Node line goes through the [Redactor](android/app/src/main/java/com/rightsubs/android/Redactor.kt) (raw and URL-encoded value → `***`).
- App network: cleartext only to `127.0.0.1`/`localhost`. Only the main Activity is exported.
- **The only port on the local network:** "Fill in on your phone" ([PhoneSetupServer.kt](android/app/src/main/java/com/rightsubs/android/PhoneSetupServer.kt)) opens an HTTP form on `<LAN IP>:7001` only while the screen is open (closes when leaving it, after 1 accepted submission, 10 min or 5 wrong codes). 6-digit code (`SecureRandom`, compared in constant time) shown on the TV and inside the QR ([QrCode.kt](android/app/src/main/java/com/rightsubs/android/QrCode.kt), checked with `zbarimg`); `Host` must be its own IP:port (against DNS rebinding); CSP without scripts, `no-store`; no typed value comes back in the page or goes to the log; every text is HTML-escaped. **HTTP without TLS inside the Wi-Fi: a risk accepted by the maintainers** (HTTPS would need a self-signed certificate and a browser warning).
- `toString()` of `Credentials`/`CredentialsForm` hides values. Never log secrets, Real-Debrid or Torrentio URLs (they carry keys).
- **Signing key:** releases use the organization's key, only in the repository secrets (and an offline backup). Never in git (`.gitignore` and the commit hook refuse `signing/`, `*.p12`, `*.jks`, `*.keystore`). A local build signs with its own `signing/` key, so it does not install over a release.

## Testing-only features

**Prefill:** `PREFILL=1 sh build.sh` (or `.\build.ps1 -Prefill`) builds `*-prefill.apk`. [scripts/write-prefill.mjs](scripts/write-prefill.mjs) copies OpenSubtitles/RD/DeepL from `.env` into `assets/prefill.json` **in plain text**; [Prefill.kt](android/app/src/main/java/com/rightsubs/android/Prefill.kt) stores it in the `SecretStore` once (flag in separate prefs: "Delete credentials" does not bring it back) and only when there are no stored credentials: **to apply it on a box that already has credentials, `pm clear com.rightsubs.android` first**. **Normal builds do not read `.env`** (the asset only exists with `PREFILL`). Never distribute a `-prefill.apk`. **`WORKING_TREE=1`** (`-WorkingTree`): the addon comes from `rightsubs/` **as it is on disk** (new files included, without committing or touching the stage), instead of the last commit. The box test flow is `WORKING_TREE=1 PREFILL=1 DEBUG_LOG=1 RUN_TESTS=1 sh build.sh` + `adb install -r` + `pm clear`.

**Barriers so credentials go nowhere:** (1) every build that is not `PREFILL` runs [scripts/check-no-secrets.sh](scripts/check-no-secrets.sh) and **deletes the APKs** if it finds `prefill.json`, `.env`/`config.yaml` or any `.env` value in them; (2) commit hook [scripts/git-hooks/pre-commit](scripts/git-hooks/pre-commit) (active with `git config core.hooksPath scripts/git-hooks`; set it up on each clone) blocks `.env`, `signing/`, keystores, `out/`, `build/`, APKs, `prefill.json`, `CLAUDE.local.md` and any `.env` value in tracked files; (3) test builds (`PREFILL`, `DEBUG_LOG`) leave `out/DO-NOT-DISTRIBUTE.txt`, warn at the end and carry the suffix in the name; (4) `.gitignore` with `*-prefill*.apk`, `*-debuglog*.apk`, `prefill.json`; (5) the release workflow refuses test builds; skills `release-check` and `new-version`. The scripts show only the variable's **name**, never the value.

Also the **adb-readable log copy** at `/sdcard/Android/data/com.rightsubs.android/files/rightsubs.log`: `DEBUG_LOG=1` (`-DebugLog`, builds `*-debuglog.apk`; `BuildConfig.DEBUG_LOG_MIRROR`, `-PdebugLog=true`; `LogFile(mirror=…)` in `NodeRuntime.kt`). Lines already go through the `Redactor`, but show the movies watched: never distribute a `-debuglog.apk`.

## Versions

The version is only in the `VERSION` file (semver): the build also injects it into the addon's `package.json` ([build-payload.sh](scripts/build-payload.sh)), so the app's status line, Stremio's manifest and the User-Agent show the APK's version; the build checks it (APK = addon = `VERSION`) and the skill `new-version` keeps `rightsubs/package.json` equal; `CHANGELOG.md` with `[Unreleased]`; each version = commit "Version X.Y.Z" + annotated tag `vX.Y.Z`, and **pushing the tag publishes the release** (GitHub Actions). `versionCode` = minutes since 1970 (always grows; the first builds already used it, so a smaller scheme would block updating over them). `out/BUILD-INFO.txt` records versions, commit (`+dirty` = does not match a commit) and the Node/ffmpeg versions. Procedure: skill `new-version`; for people, README › Releases.

## Test devices

- Xiaomi TV Box S 3rd gen (`MiTV_AFMU0`, "twilight"): Android 14, **32-bit userland (armeabi-v7a)**, Wi-Fi 6. No Termux.
- Chromecast with Google TV 4K: Android TV 14, 32-bit userland (`armv8l`), 2 GB RAM.
- NVIDIA Shield TV Pro (Android 11, arm64).
- Redmi 5G phone (Android 16): portrait screen (`layout/`) and the Install in Stremio button.
- Access through **adb over the network from inside the container** (`scripts/adb.sh`, key in the Docker volume `rightsubs-adb`). Network debugging on only for tests; remind the user to turn it off afterwards. Box workflow: skill `box`.
- Installing in Stremio: Stremio turns **any** `stremio://` into `https://` (even `stremio:///addons?addon=http…`; measured on the Shield, Stremio 1.12.0), and the addon is `http`. So the button opens `web.stremio.com/#/addons?addon=…` on a phone and, on a TV (`UI_MODE_TYPE_TELEVISION`; Google TV has no browser and opens a stub without an error), only shows where to type the address (Addons › Add addon). Copying does not help: the TV's Gboard has no paste and holding OK on the field only reopens the keyboard (measured on the Shield); pasting only works through the Google TV app keyboard on a phone.
- **Stremio on the box (Android TV) × a slow addon:** Stremio gives up on a request **10 s after the first request to the addon** and, if the `.srt` has not arrived, the **video does not even open** (measured: an answer at 12.8 s failed, at 5.9 s worked). Any track that may take long answers first with a provisional subtitle; today only the pending translation (3 s). Stremio has no pop-up for addons, and the `lang` field of the list is the track's name. [DEEPL-TRANSLATION.md](rightsubs/docs/DEEPL-TRANSLATION.md).

- **Addon (`rightsubs/`, 237 tests passing):** multi-provider search, ranking and sync by reference (exact OpenSubtitles subtitle, embedded text track, or a release of the same edition); a notice only when the video already has an embedded track in the user's language; **DeepL translation** as a last resort, always checked against the embedded track (6 windows), with "timing not confirmed" for movies without one (series no); text cleanup of every subtitle (`rightsubs/src/subtitles/clean.ts`); `stremio` source (torrents without Real-Debrid via `127.0.0.1:11470/stats.json`, ffprobe only); separate reference language (`sync.referenceLanguages`, default `en`). - **When changing a rule** for choosing or syncing: update `rightsubs/CLAUDE.md`, README › "How the subtitle is chosen and synced" and `rightsubs/docs/` (`CONFIGURATION.md` › `sync`, `FINDINGS.md` with the real case).
- **Heavy-file measurements** (Drive OpenMatte 60 fps, 23.6 GB; details in `rightsubs/docs/FINDINGS.md`): Real-Debrid delivers 113 Mbit/s on the PC and 142–151 on the box, parallel does not add bandwidth; the minimal ffmpeg equals the full one; reading a window with the subtitle track takes ~4× longer than audio only (9.7 s × 41–44 s), for an internal ffmpeg reason **not found yet** (also in Debian's ffmpeg 5.1); smaller windows do not work (with fewer than ~44 cues the alignment fails); EXO waits at least 34 s for the `.srt`, repeating the request every ~10 s.

- **Pending:** the **focused** primary button uses `accent_focused` `#9580F7` with white text, hard to read on a TV (fix proposed, not approved: background `accent` `#7B5BF5` and only the white ring); `layout/` was only exercised on the box (`wm size 1080x2340`); a Downloader short code for the release links.

## Pitfalls already met

- PowerShell 5.1: `$ErrorActionPreference='Stop'` + stderr from `docker`/`git` = false error; the `.ps1` files need a UTF-8 BOM and check `$LASTEXITCODE`.
- Git Bash + Docker: use `D:/…` paths and `MSYS_NO_PATHCONV=1`; `git -C x archive -o` is relative to `x` (use an absolute path).
- Scripts for the box: write them to a file, strip `\r` and send with `adb push` (nested quotes in `adb shell "…"` break); `pkill -f pattern` kills its own shell.
- Termux's Node uses OpenSSL's CA store: without `SSL_CERT_FILE` it gives `UNABLE_TO_GET_ISSUER_CERT_LOCALLY` (the app sets it).
- `real-debrid.com/d/…` is an HTML page; ffmpeg needs the direct `*.download.real-debrid.com/d/…` link. RD links are valid for the home IP (PC and box go out through the same one).
- Auto mode blocks downloading third-party binaries (e.g. ffmpeg builds on GitHub); use Debian packages (`apt`) in the container.
- **The app screen is `FLAG_SECURE`**: adb `screencap` does not show the look. Check through `logcat` (resource/inflate errors: filter `AndroidRuntime|FATAL EXCEPTION|InflateException`; `NotFoundException` matches Play Store noise) and a photo of the TV. To exercise the phone `layout/` on the box: `wm size 1080x2340; wm density 420` and then **`wm size reset; wm density reset`**.
- **Initial D-pad focus:** without a request, Android picks the first focusable item, which was `manifest_url` (`textIsSelectable` makes it focusable). The opening focus comes from `<requestFocus />` on the `install_stremio` button in both `main_actions.xml`; `showForm()`/`hideForm()` request focus in code.
- On a TV (3 selectors side by side) the label "Secondary (when there is no primary)" may wrap to 2 lines: the 3 labels have `minLines="2"` + `gravity="bottom"` in `layout-w720dp/languages.xml` so the selectors line up. Longer label text (Portuguese is longer than English) needs the same care.
- The widgets' parent styles (`Widget.DeviceDefault.*`) set their own `fontFamily`, `background` and state animator: that is why `Action`/`Field` repeat the font and `Action` clears `stateListAnimator`. Removing the button's default background also removes its vertical spacing (hence `layout_marginBottom` 8 dp in `Action`).
