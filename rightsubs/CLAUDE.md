# RightSubs (addon) — context for Claude

Node.js Stremio addon that serves **one** subtitle, already chosen and **synced**, in the primary language (default pt-BR) or, with none in the primary, in the secondary (default pt-PT). The user's goal: pick any file, press play and watch — without choosing a player or subtitle, or adjusting the delay.

**Where it runs:** inside this repository's APK (Android TV/Google TV and phones). Box, build, install, credentials and the box workflow: the root `CLAUDE.md` and skills `box`/`build-apk`. **No Termux or ssh**; the app generates `config.yaml` (`ConfigWriter.kt`) and supervises Node (`AddonService.kt`: exit code 78 = invalid config, no restart; 75 = clean restart). The addon lives only here (it started as a copy of the standalone right-subs project on 2026-11-01). **Language rule** (root `CLAUDE.md`): everything in English, except the viewer messages in `src/i18n/messages.ts`.

Documents: [docs/CONFIGURATION.md](docs/CONFIGURATION.md) (every option), [docs/FINDINGS.md](docs/FINDINGS.md) (measurements and **real test cases**), [docs/NEXT-STEPS.md](docs/NEXT-STEPS.md) (pending and deferred), [docs/DEVELOPMENT-PLAN.md](docs/DEVELOPMENT-PLAN.md) (original architecture, history).

## How the subtitle is chosen (as of 2026-11-07, 237 tests)

- **0. Embedded track in the user's language (comes before everything)** (`SubtitleService.embeddedLanguage`, `embeddedLabel`/`embeddedNoticeSrt` in `src/stremio/status.ts`, `handleSubtitles` in `src/app.ts`; maintainers' decision on 2026-11-04, **always**, not only before DeepL): when listing subtitles, the addon locates and probes the file (`ffprobe`, header, ~1–1.5 s). If there is a **non-forced track of any codec** (text or image) in the primary and then in the secondary, the flow **ends there**: no search, download, sync, DeepL or video reading; it answers only the `rightsubs-embedded` entry, whose name (`lang`) is the notice "the video already has an embedded subtitle in your language, pick it in the menu" (not a language code, so Stremio does not pick it instead of the file's track); if picked, it shows the notice for 20 s. It does not depend on `sync.embedded.enabled` (only on `ffprobe` and locating the file). Without a probe (file not located, network down) the normal flow goes on. Extracting the track was ruled out: in MKV the cues are spread out, reading them all = the whole file. **Measured on the box** (Chef's Kiss NoRBiT, Creature Commandos S01E03): Stremio lists the file's track and does not pick the notice; the notice itself does not show in the left menu nor on screen (maintainers' decision: keep it that way). Tracks only in other languages (Narco Mennonites: EN and FR) do not trigger the notice.
- **Viewer messages** (`src/i18n/messages.ts`): the subtitle-menu entries, on-screen notices, the translation notice and the manifest description are in the **primary language** (`config.languages.primary`), whatever the language of the subtitle served; one fixed translation per language in `LANGUAGES` (16), English for any other. `test/messages.test.ts` checks every language has every text, with the same placeholders and line breaks. A new message goes into all 16 (and the maintainers review the translations).
- **Search** (`src/subtitles/`): all providers in parallel, languages = primary + secondary + `sync.referenceLanguages` (default `[en]`: reference only, never served). Offers **one** track, URL `/sub/{type}/{id}/{lang}/{filename base64url}.srt`, the same in both Stremio requests (the 2nd carries the hash). Download only when the player asks: the v3 copy (no quota, `sameAs` = `legacy_subtitle_id`) before the API (20/day). `normalizeFilename` (`src/stremio/request.ts`): Stremio sometimes sends the RD link (raw or encoded) or `realdebrid:ID:1` as `filename` — only the file name is used and the link is never logged.
- **Ranking** (`src/subtitles/rank.ts`): exact > group (+80) > source bluray/web/hdtv/dvd (±) > resolution; fps inferred from the exact ones (±30); SDH −10; free or cached +15. `isExact` = hash, or a release name of ≥ 5 tokens contained in the file name **and the same edition** (DC/Director's Cut, Extended, Uncut, Unrated, Theatrical, IMAX). Without sync confidence, it tries the next **free** candidate.
- **Sync** (`src/subtitles/service.ts`, `src/sync/`), stops at the first that applies:
  1. **exact** OpenSubtitles reference (any language searched; free first) → `align.ts`: offset voting between cue starts + 7 fps ratios, score = speech overlap and cues starting together (±0.5 s; Drive); applied if confidence ≥ `minConfidence` and gain ≥ 0.1 (or ≥ 0.25 on cues starting together);
  2. `likely_synced`: same edition, source and resolution as the file → the video is not read (maintainers' decision: be conservative);
  3. **embedded** (`embedded-reference.ts`): non-forced text track, preferring the reference languages (`pickTextTrack`), 3 windows of 45 s in the parts with the most dialogue, read in parallel with `ffmpeg -copyts -ss … -to …`; per-window time limit proportional to the bitrate (`windowTimeoutMs`, 15 s to 2 min; Drive ~85 s). The player waits for the extraction (maintainers' decision). Off for `peerToPeer` files;
  4. `same_edit`: a release of the same edition, source and resolution (another group), any language;
  5. `fps_corrected`: fps only, from the real fps (ffprobe, `r_frame_rate`, standard rates only); rescales at most 5% (never 23.976 → 59.94 on interpolated video).
  Status in the `subtitles.served` log: `exact`, `synced`, `already_synced`, `likely_synced`, `fps_corrected`, `no_reference`, `low_confidence`, `budget_exceeded`, `disabled`.
- **File playing** (`src/streams/locator.ts`), chain proxy (indexers) → RD API (`/downloads`, the link shows up on the 2nd request) → Stremio's local server (`src/streams/stremio.ts`, `127.0.0.1:11470/stats.json`, by name and size; torrent without RD, `peerToPeer`: ffprobe with 15 s, no embedded track). The APK uses companion mode (no indexers).
- **Translation (last resort)** (`#translate`, `src/sync/consistency.ts`, `src/translation/`, `src/stremio/status.ts`): with nothing in the primary or secondary, translates with DeepL the best subtitle in **any language** whose timing the embedded track confirms in 6 windows (both halves agree); refuses subtitles from another cut (steps). A provisional subtitle after 3 s while translating (Stremio's 10 s limit). Rules, measured constants and logs: [docs/DEEPL-TRANSLATION.md](docs/DEEPL-TRANSLATION.md).
- **Text cleanup (always, at the end)** (`src/subtitles/clean.ts`, applied in `prepare`): every subtitle served (online, translated) loses musical notes (♪ ♫ ♬ ♩ ♭ ♯) and their corrupted form (`â™ª`: UTF-8 read as Windows-1252, it came from the English source subtitle and DeepL kept it; Chef's Kiss RGB), the replacement character, control/invisible characters, `#` used as a music mark (`#1` and `#hashtag` stay) and leftover ASS (`{\an8}`, `\N`, `\h`); cues left empty go away. `<i>` and `<font>` stay (the player draws them). An already clean subtitle comes out identical, byte for byte.
- **Accepted/open limitations:** with no text reference at all it goes out `no_reference`, even with a wrong declared fps or an edition under another name (Enter the Void r00t "Extended") — a case for **audio** syncing (deferred). The secondary only comes in when there is **no** subtitle in the primary (`useSecondaryWhen: low_confidence` accepted, not applied; maintainers' decision).
- **Real cases** (Valkyrie Licdom +25.5 s, Halloween QTZ/Tigole, Drive OpenMatte −12.82 s, Enter the Void DC ×0.95904, White Ribbon, Death Note, Matlock, Generation Z S01E01 for the translation: DE accepted with +6.0 s, EN/ES refused): table in [FINDINGS.md](docs/FINDINGS.md#real-test-cases-known-answers). **When changing sync or ranking, repeat the affected cases** and record the result there.

## Decisions already made (do not reopen)

| Topic | Decision |
|---|---|
| Player | **EXO** in Stremio (4K HDR/Dolby Vision/Atmos). On phones, Stremio's VLC draws external subtitles badly (its bug): use ExoPlayer. |
| Languages | Set on the APK screen: primary pt-BR, secondary pt-PT, reference `en`. Watched × reference are different things. |
| Sources | OpenSubtitles API (**free** account) for search + OpenSubtitles v3 addon (no account, no quota) for downloads. Pluggable providers through config. |
| Translation | **Last resort, DeepL Free** (2026-11-03, done and validated on the box): only with no subtitle in the primary or secondary. The source can be in **any language** (the search covers them all when there is a translator): up to **8** candidates with distinct timing, the free ones (v3) first and the API ones only if none works; an exact one that checks out wins at once. Each is checked against the embedded track (**6 windows** of 45 s, never the whole video) and only counts if **one offset and scale fit the whole movie** (`checkConsistency`: 1st × 2nd half). The highest confidence wins; a tie (≤ 0.02) = English, then the others. `likely_synced` is **not** enough. With no embedded track to check: only exact (as it is) or synced by another subtitle; **only for movies**, and only if nothing else worked, translates the best candidate with the **same fps** with the "timing not confirmed" notice (maintainers' decision; series no). **Out of scope, by the maintainers' decision:** translating the whole embedded track (needs reading the whole movie). The translation carries an AI notice and loses the `<font>` tags (Stremio's style applies). **First time:** Stremio gives up after 10 s (counted from the 1st request to the addon; on the box the video does not even open), so, if the translation is not ready in 3 s, the track answers a provisional "open it again in ~30 s" subtitle and the translation finishes in the background. The timing check **only exists with Real-Debrid** (Stremio torrents and other debrids: see the table in DEEPL-TRANSLATION.md; without Real-Debrid, not tested). Key in `DEEPL_API_KEY`; `translation.deepl.forceFrom` is for testing only. All in [docs/DEEPL-TRANSLATION.md](docs/DEEPL-TRANSLATION.md). |
| Services | **Free ones only** (besides each person's RD, optional). |
| Where it runs | On the Stremio device (RD restricts IPs). Nothing in the cloud. |
| Resources | **Strong requirement:** use resources only while Stremio uses the addon; idle at the floor (plan §6.1). Measured on the box: Node ~40 MB, app ~35 MB. |
| Golden set | None: a title out of sync → the user brings it for analysis (log + measurement). |
| Cache | 50 MB, **10 days** since last use. |

## Code conventions

- TypeScript with **erasable syntax** (`erasableSyntaxOnly`): no enums, namespaces or parameter properties. Relative imports with the `.ts` extension.
- `npm run dev` runs the TS directly (Node ≥ 22.18); the device runs the compiled `dist/` (`npm run build`; TS directly would cost ~20 MB more). The APK build does `npm ci --ignore-scripts`, build and `npm prune --omit=dev`.
- Runtime dependencies: only `yaml` and `zod` (v3). **No native modules** (Termux's Node on Android). Avoid new dependencies; if needed, small pure JS.
- HTTP with `node:http` + own router (`src/http/router.ts`), no Express/Stremio SDK.
- Identifiers, comments, logs, error messages and docs in **English**. Text the viewer reads inside Stremio goes through `src/i18n/messages.ts` (never a hard-coded string).
- Config: zod with plain English messages (`src/config/errors.ts`), `.strict()` objects, secrets through `${VAR}` (in the APK, process environment variables; never a file). The APK depends on the format of `config.example.yaml` (`ConfigWriterTest`) and on the list in `src/languages/languages.ts` (`LanguagesTest`): when changing either, run the app tests. A new language in `languages.ts` also needs its translation in `src/i18n/messages.ts`.
- Providers: `ProviderType` in `src/providers/`, registered in `src/providers/index.ts`; `stremio-addon` = any addon by URL ([NEW-PROVIDER.md](docs/NEW-PROVIDER.md)).
- Tests: `node:test` in `test/*.test.ts` (`npm test`). Every new behavior comes with a test.
- Logs: one line per event, `<iso> <LEVEL> <event> {json}` (`src/logger.ts`). Never log secrets, RD links or indexer URLs (they carry the key).

## Resource rules (for all new code)

- A heavy task uses `resources.idle.beginJob()` and releases it when done; at most `resources.maxConcurrentJobs`.
- In-memory structures register their release in `resources.onIdle(...)` and have an item/age limit.
- No `setInterval`/polling. Timers armed only by activity, with `unref()`.
- ffmpeg: `-threads 1`, timeout, kill the child process on abort/stop; audio over HTTP range through a **pipe**, no temporary file; video never written to disk.
- Temporary files only in `resources.tmpDir` (emptied on start/idle).
- Disk cache: update `mtime` on every use (the janitor deletes by `mtime`).
